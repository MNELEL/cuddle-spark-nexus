# ניתוח פערים — LMS Capabilities

מסמך זה ממפה את יכולות המערכת הנוכחיות של ״הכיתה שלי״ מול רשימת יכולות LMS סטנדרטית, ומציג תוכנית יישום לסגירת הפערים החשובים.

## סטטוסים

- ✅ **מלא** — יכולת קיימת ופעילה בייצור.
- ⚠️ **חלקי** — יכולת קיימת אך דורשת חיזוק, הרחבה או אוטומציה נוספת.
- ❌ **חסר** — יכולת לא קיימת ונדרשת לפי תוכנית היישום.

---

## 1. אבטחה וניהול משתמשים (Security & User Administration)

| תת-יכולת | סטטוס | פרטים |
|---|---|---|
| אימות והרשאות (Auth) | ✅ | Supabase Auth עם מייל/סיסמה ו-Google OAuth. |
| שחזור סיסמה | ✅ | מייל איפוס + עמוד `/reset-password` עם טיפול בקישורים פגים. |
| נעילת PIN | ✅ | טבלת `app_security` עם מערכת PIN (מוצפן, ללא שמירת plain text). |
| תפקידים והרשאות (RBAC) | ❌ | אין טבלת `user_roles` — כל משתמש הוא בעל הכיתה שלו בלבד. לא ניתן למנהל/מנצח/מזכירה לגשת לנתונים. |
| ניהול משתמשים במסוף | ⚠️ | ניתן לנהל כיתות ותלמידים, אך לא משתמשי מערכת אחרים. |
| נעילת חשבון והגנת brute-force | ⚠️ | מוגבל לכללי Supabase Auth; אין rate-limit מותאם אפליקציה. |

**פעולה נדרשת:**
- יצירת טבלת `user_roles` עם תפקידים (`admin`, `principal`, `teacher`, `secretary`).
- הוספת מדיניות RLS מבוססת `has_role()`.
- יצירת מסך ניהול משתמשים למנהל מוסד.

---

## 2. ניהול קורסים/מסגרות לימוד (Course Management)

| תת-יכולת | סטטוס | פרטים |
|---|---|---|
| יצירת כיתות | ✅ | כיתות עם הגדרות גריד, מקומות פנויים, אובייקטי סביבה. |
| יומן/לוח אירועים כיתתי | ✅ | טבלת `class_events` עם סוגי אירועים (מבחן, טיול, חג, יום הולדת וכו׳). |
| תוכנית שבועית | ✅ | טבלת `weekly_lessons` — שעות, מקצועות, שיעורים. |
| סידור הושבה | ✅ | מערכת הושבה 2D + 3D, חוקים, קבוצות, צרכים מיוחדים. |
| קבוצות לימוד | ✅ | טבלת `groups` ושיוך תלמידים לקבוצות. |
| מסלולי/יחידות לימוד | ❌ | אין אובייקט של "יחידת לימוד" או "מסלול" עם מטרות/תוצרים. |
| קישור מקצוע-כיתה | ⚠️ | מקצועות נקראים מ-text חופשי; אין taxonomy מוסדי רשמי. |

**פעולה נדרשת:**
- הוספת טבלת `curriculum_units` או `course_units` המקשרת מקצוע, נושאים ותוצרי לימוד.
- שיפור taxonomy של מקצועות קודש עם קודים מוסדיים.

## 3. ניהול משאבי למידה (Learning Resource Management)

| תת-יכולת | סטטוס | פרטים |
|---|---|---|
| מעלית חומרים (Resources) | ✅ | טבלת `teaching_resources` עם סוגים, נושאים, תגיות ומטא-דאטה. |
| ספרייה/אוספים | ✅ | טבלת `resource_collections` + `resource_collection_items`. |
| סיווג אוטומטי של קבצים | ✅ | Smart Ingest מבצע OCR וסיווג AI. |
| חיפוש סמנטי | ✅ | embeddings + `match_resources()` על pgvector. |
| תיאור התקדמות בתלמיד | ⚠️ | נתוני ציונים/נוכחות קיימים, אך אין מסלול למידה אישי. |
| מנגנון שיתוף משאבים | ⚠️ | משאבים שייכים למורה בלבד; אין שיתוף בין מורים או מוסדות. |

**פעולה נדרשת:**
- שיתוף משאבים ברמת מוסד (school-level) עם הרשאות צפייה/עריכה.
- מנגנון הגירסאות/היסטוריה למשאבים.

## 4. אינטגרציות וממשקי API (Integrations & APIs)

| תת-יכולת | סטטוס | פרטים |
|---|---|---|
| API פנימי (server functions) | ✅ | `createServerFn` לכל פעולות האפליקציה. |
| API ציבורי (webhooks) | ✅ | נקודות קצה ב-`/api/public/*` (כגון webhooks). |
| אינטגרציה עם Google | ✅ | Google OAuth + Google Search Console. |
| ייבוא/ייצוא נתונים | ✅ | CSV/XLSX לתלמידים, ציונים, נוכחות ומשאבים. |
| אינטגרציה עם מערכות חיצוניות (Moodle, Google Classroom, LMS אחרים) | ❌ | אין חיבורים לשירותי LMS חיצוניים. |
| MCP / agent integration | ⚠️ | הוכן scaffolding, אך לא הושלם חיבור agent. |

**פעולה נדרשת:**
- אינטגרציה עם Google Classroom (ייבוא כיתות/מטלות) ולוח שנה.
- חיבור MCP server מאובטח (OAuth) לסוכני AI.

## תוכנית יישום מוצעת

### שלב 1: יסודות אבטחה ו-RBAC (מיידי)
1. יצירת טבלת `user_roles` ופונקציית `has_role()`.
2. מדיניות RLS לכל טבלאות הליבה לפי תפקיד.
3. מסך ניהול משתמשים למנהל מוסד.
4. הגדרת מפתחות API וסודות נוספים לפי הצורך.

### שלב 2: אינטגרציות ו-API (2-3 שבועות)
1. חיבור Google Classroom API.
2. השלמת MCP server מאובטח (OAuth).
3. יצירת נקודות קצה ציבוריות נוספות ל-webhooks.

### שלב 3: שיתוף ותקשורת (2-3 שבועות)
1. שיתוף משאבים בין מורים/מוסדות.
2. Push notifications + SMS reminders.
3. צ׳אט/פורום צוות.

### שלב 4: דוחות וניהול מוסדי (3-4 שבועות)
1. דשבורד מנהל מוסד.
2. report builder.
3. ייצוא נתונים לסטנדרטים (JSON/CSV).

### שלב 5: מובייל ו-offline (3-4 שבועות)
1. PWA manifest ו-service worker.
2. מצב offline בסיסי.
3. אפליקציית iOS (Capacitor).

---

## סיכום

המערכת מכסה היטב את הצרכים של מורה בודד: אבטחה בסיסית, ניהול כיתה, משאבי למידה, תקשורת עם הורים ודוחות. הפערים המרכזיים הם **RBAC** (ניהול מוסדי), **אינטגרציות חיצוניות**, **תקשורת צוותית**, **דוחות מוסדיים** ו**מובייל מתקדם**. תוכנית השלבים מעלה מספקת מסלול יישום בר-קיימא לבניית פתרון LMS מלא לארגוני חינוך תורניים.
