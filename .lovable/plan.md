# תוכנית עבודה: איפוס סיסמה, LMS Gap Analysis ומיתוג תורני

## 1. תיקון עמוד /reset-password — קישור פג/לא תקף

הקיים כיום: העמוד בודק סשן בטעינה ומציג `"הקישור אינו תקף או פג תוקפו. בקש קישור חדש ממסך הכניסה"` בתוך פס אדום, אך אין פעולה ברורה למשתמש.

יעדים:

- הצגת מצב "קישור פג" ככרטיסיית שגיאה מובחנת (ללא טופס סיסמה) כאשר `supabase.auth.getSession()` אינו מחזיר סשן.
- הוספת כפתור "בקש קישור חדש" שמפנה ל-`/login` ומסמן את אזור הסטטוס שם כך שהמשתמש ידע ללחוץ על "שכחתי סיסמה".
- טיפול בשגיאת `updateUser` כאשר הטוקן פג גם אחרי שהסשן נטען — הצגת הודעה ברורה וכפתור חזרה.
- שמירה על נגישות: `aria-live="assertive"` לשגיאה פגיעה, מיקוד על הכותרת/כפתור בעת מעבר למצב שגיאה.

קבצים לעריכה:

- `src/routes/reset-password.tsx` — הוספת מצב `invalid` ו-UI חלופי.
- `src/routes/login.tsx` — תמיכה ב-state חיצוני (לדוג' `?reset=expired`) כדי להציג הודעה מובנית מעל הטופס.

## 2. Gap Analysis — יכולות LMS שקיימות וחסרות

נערוך מסמך גאפ-אנליזיס מובנה ב-`docs/lms-gap-analysis.md` (או במתאים לפרויקט) שממפה כל קטגוריה לטבלאות, ל-server functions ולמסכים קיימים.

טיוטת מיפוי ראשונית מהקוד הנוכחי:

| קטגוריה | קיים באפליקציה | חסר / דורש חיזוק |
|---|---|---|
| Security / User administration | אימות Supabase, PIN lock, `app_security`, `app_logs`, JWT | טבלת `user_roles` + `has_role`, מסך ניהול משתמשים/תפקידים, SAML/SSO |
| Course management | כיתות, תלמידים, הושבה, נוכחות, ציונים, קבוצות, יומן אירועים, לוח פעמונים, מערכי שיעור | מסלולי למידה (learning paths), תבניות כיתה, מיפוי קурריקולום רשמי |
| Learning resource management | ספריית חומרי הוראה, אוספים, מאגר שאלות, AI, taxonomy, העלאת קבצים | חוזקה — קיים ברובו |
| Integrations / APIs | Lovable AI Gateway, עמודי שיתוף ציבוריים | אין תיקיית `src/routes/api/`, אין webhooks, אין LTI/SIS/API keys |
| Communication & collaboration | מיילים להורים, סקרים כיתתיים, תזכורות, מודעונים | צ'אט/מסרים מיידיים, פורומים, שיחות ועידה |
| Reporting | דוחות כיתה, analytics, insights, תעודות, התנהגות | חוזקה — קיים ברובו |
| Customization | 6 ערכות נושא, הגדרות מיתוג, RTL | למידה מותאמת אישית (adaptive) לפי ביצועים |
| Mobile | Capacitor Android config | אופטימיזציה ניידת, offline sync, iOS |

## 3. תכנית יישום של יכולות חסרות (מומצעת)

ניתן לחלק לשלבים קטנים וניתנים למדידה. המלצה:

### שלב 1: אבטחה ו-RBAC

- יצירת `public.user_roles` + `app_role` enum + `has_role()` SECURITY DEFINER.
- GRANTs ו-RLS policies מתאימים.
- מסך "ניהול משתמשים" מינימלי לתצוגת תפקידים ושיוך מנהלים (רק admin).

### שלב 2: ממשקי API ושילובים חיצוניים

- יצירת `src/routes/api/public/*` עבור:
  - Webhook כללי מאומת (`/api/public/webhook`) לשילוב SIS/כלים חיצוניים.
  - נקודת קצה לקריאת נתוני כיתה מנורמלים (`/api/public/class/{token}`) כבסיס ל-LTI.
- טבלת `api_keys` עם יכולת ניהול במסך הגדרות.

### שלב 3: תקשורת ושיתוף פעולה

- הרחבת הסקרים כך שיתמכו בזיהוי תלמיד ותוצאות אנונימיות.
- הוספת "מודעון כיתה" עם תגובות (פורום מובנה) או צ'אט קבוצתי פשוט.
- שילוב תזכורות מול תלמידים/הורים ב-WhatsApp/SMS אופציונלי.

### שלב 4: התאמה אישית ולמידה מסתגלת

- שימוש ב-`teacher-style.functions.ts` ו-`performance-score.ts` להמלצות תוכן מותאמות לתלמיד ספציפי.
- הצעת חומרי הוראה ותרגילים לפי רמת הביצועים בנושא.

### שלב 5: מובייל

- עדכון `capacitor.config.ts` לשם ולמזהה העבריים.
- הוספת service-worker פשוט ל-cache של נכסי PDF/סאונד.
- בדיקת תאימות מסכים קטנים במסכים הכי נפוצים (`login`, `classes`, `resources`, `daily`).

## 4. מיתוג וסמל — סגנון תורני

המשתמש ביקש לעדכן כותרת, תיאור וסמל בשני המישורים: מיתוג הפנימי של האפליקציה ומטא-נתונים של הפרויקט ב-Lovable, בסגנון תורני.

### 4.1 מיתוג פנימי (בקוד)

- כותרת מוצעת: "הכיתה שלי · סטודיו לניהול כיתה תורנית"
- תיאור מוצע: דגש על תלמודי תורה, חיידרים, בתי ספר, מקצועות קודש, ערכים תורניים.
- סמל מוצע: החלפת `GraduationCap` (כובע סטודנט) בצלמית תורנית — למשל ספר (`BookOpen` / `BookText`), ספר תורה (`Torah` icon מ-Lucide או SVG מותאם), או מנורת שבעת הקנים.
- עדכון מטא-תגים, JSON-LD, `public/llms.txt`, ו-OG image כך שיישקפו את המיתוג התורני.
- עדכון `src/routes/__root.tsx`, `src/routes/index.tsx`, `src/routes/login.tsx`, והעמודים הפומביים.

### 4.2 מטא-נתונים של Lovable

- עדכון שם הפרויקט, התיאור והסמל בלוח הבקרה של Lovable.
- נדרשת אימות/הרשאה — יש לבצע דרך ממשק Lovable (לא בקוד בלבד). ניתן לסייע בהכנת הטקסטים והאייקון המותאמים.

## 5. קריטריוני הושלמות

- `/reset-password` מציג כרטיסיית שגיאה ברורה עם כפתור "בקש קישור חדש" כאשר הקישור פג/לא תקף.
- `/login` מציג הודעת מעבר ברורה כאשר מגיעים מקישור פג.
- קיים מסמך gap-analysis מובנה עם טבלת 8 הקטגוריות.
- יש תכנית יישום שלבים 1–5 לפחות עד רמת server functions + routes מועדפים.
- מיתוג תורני מיושם בקוד (כותרת, תיאור, סמל, מטא-תגים) ומוכן להעתקה ל-Lovable project metadata.
- בדיקות: `tsgo` עובר; Playwright מוודא את מצב השגיאה ב-`/reset-password`.

## 6. הערות טכניות

- עמוד `/reset-password` מסתמך על סשן מוגדר על ידי Supabase reset-password flow. כל שיפור חייב לשמור על התנהגות זו.
- אין ליצור `user_roles` ללא GRANTs ו-RLS policies — יש לפעול לפי הכללים הנהוגים בפרויקט.
- אין לשמור סיסמאות/קודים כ-plaintext; יש להשתמש ב-SECURITY DEFINER לבדיקת תפקידים.
- סמל תורני מותאם ישמר ב-`public/` וייקשר ב-`__root.tsx` כ-favicon/OG image במידת הצורך.
